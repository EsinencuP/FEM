# План разработки FEM

Версия: 3.0

Дата: 2026-07-24

Подробный исполняемый план: `../../FEM_MVP_ACCELERATED_PLAN.md`.

## Цель

Сначала подготовить существующие БД и Admin API к frontend, затем собрать
минимальный demo-интерфейс учёта.

## Поток 1. DB/API readiness

Статус: **PASS**.

Оценка: **1–2 дня**.

1. Вернуть зелёный baseline.
2. Применить миграции к чистой PostgreSQL 16.
3. Подготовить презентационный повторяемый seed.
4. Проверить спортсменов, лошадей, соревнования, классы и результаты.
5. Подтвердить filters/sort/pagination.
6. Добавить только недостающие человекочитаемые проекции.
7. Обновить OpenAPI и contract tests.

## Поток 2. Demo frontend

Статус: **PASS**.

Оценка: **2–3 дня после DB/API gate**.

1. Создать защищённый frontend shell.
2. Реализовать таблицу и карточку спортсмена.
3. Реализовать таблицу и карточку лошади.
4. Реализовать таблицу соревнований.
5. Реализовать соревнование с категориями/классами и результатами.
6. Добавить минимальные create/update формы.
7. Проверить URL state, empty/error и desktop layout.

## Поток 3. Integration/preview

Статус: **PASS для локального production preview; CONDITIONAL для внешнего
HTTPS preview из-за отсутствия hosting access**.

Оценка: **1 день**.

1. Подключить frontend к demo-БД через Admin API.
2. Пройти сценарий.
3. Исправить только P0-дефекты.
4. Разместить demo или подготовить стабильный локальный preview.

## После demo

По обратной связи:

1. Excel preview/import.
2. Archive/restore и audit UI.
3. Обучение операторов.
4. Реальные данные и backup.
5. Публичный сайт и другие модули — только отдельным scope.

## Архитектурная граница

```text
demo-web → NestJS Admin API → PostgreSQL
```

Не добавлять Public API, worker, queue, Redis, microservices, search engine или
универсальный ETL для первого показа.
