# Frontend Anti-patterns

Версия: 1.0  
Дата: 2026-07-23

Ниже перечислены решения, которые не принимаются без отдельного ADR или зафиксированного
исключения.

## 1. Визуальные значения внутри компонента

Плохо:

```css
.profile-card {
  color: #09111f;
  padding: 17px;
  border-radius: 13px;
}
```

Правильно:

```css
.profile-card {
  color: var(--fem-semantic-color-text-primary);
  padding: var(--fem-semantic-space-md);
  border-radius: var(--fem-semantic-radius-card);
}
```

## 2. Primitive token в product UI

`--fem-primitive-color-blue-600` описывает палитру, а не назначение. Product UI использует
`--fem-semantic-color-interactive-accent`. Иначе тема или редизайн потребуют массового поиска по
компонентам.

## 3. Один компонент на один макет

Копии `BlueButton`, `HeroButton`, `TableButton` запрещены, если отличаются только размером,
вариантом или состоянием. Используется единый Button API с ограниченным набором вариантов.

## 4. Boolean explosion

API вида `primary`, `secondary`, `small`, `compact`, `danger`, `rounded` создаёт несовместимые
комбинации. Предпочтительны перечислимые свойства: `variant`, `size`, `tone`.

## 5. div вместо семантики

Кликабельный `div`, ручная таблица на flexbox и заголовок через увеличенный `span` запрещены, если
HTML уже имеет подходящий элемент.

## 6. Placeholder как label

Placeholder исчезает при вводе и не заменяет видимый label. Он может показывать пример формата, но
не название поля.

## 7. Цвет как единственный статус

Красная строка без текста или иконки не объясняет ошибку всем пользователям. Статус имеет
читаемое имя и доступное описание.

## 8. Отключение focus outline

`outline: none` без равноценного `:focus-visible` запрещён. Focus должен быть виден на светлой,
тёмной и статусной поверхности.

## 9. `!important` как архитектура

`!important` маскирует неуправляемую специфичность. Исправляется слой, ownership стилей или API
варианта. Stylelint блокирует это автоматически.

## 10. Глобальный selector reach

Селектор `.page .sidebar ul li button svg` связывает несвязанные компоненты. Компонент владеет
своим корнем и публичными variants; родитель управляет layout, а не внутренней разметкой.

## 11. Viewport-only адаптивность

Компонент, работающий только в одной ширине страницы, плохо переиспользуется. При возможности
используются container queries, fluid size и ограничение содержимого.

## 12. Автоматическое превращение таблицы в карточки

Карточки могут уничтожить сравнение колонок. Mobile-представление выбирается по задаче: scroll,
priority columns, disclosure или отдельный summary.

## 13. Бесконечный scroll для официальных данных

Для результатов, рейтинга и административных журналов необходимы стабильная пагинация, URL,
позиция и повторяемый экспорт. Infinite scroll допускается только для соответствующего контентного
сценария.

## 14. Optimistic update критических данных без отката

Публикация, результат, рейтинг и архивирование не показываются как успешные до подтверждения
backend. Если optimistic UI разрешён для безопасного действия, обязательны rollback и сообщение об
ошибке.

## 15. Скрытая backend-ошибка

`catch(() => [])` превращает сбой в «нет данных». Ошибка, пустой ответ, запрет доступа и частичные
данные — разные состояния.

## 16. Raw backend message в UI

Пользователь получает утверждённый безопасный текст и `requestId`. Stack trace, SQL, endpoint
internals и непроверенный `message` не выводятся.

## 17. Проверка доступа только в frontend

Скрытая кнопка улучшает UX, но не является authorization. Backend проверяет каждую Admin-операцию.

## 18. Секреты и приватные данные в клиенте

API keys, service credentials, закрытые projection fields и персональные данные не помещаются в
bundle, analytics, error reporting, browser storage или mock fixtures.

## 19. Snapshot update без анализа

`--update-snapshots` не является исправлением теста. Изменение baseline принимается только после
сравнения, проверки light/dark, responsive и объяснения причины.

## 20. Ручная правка `tokens/build`

Generated output всегда будет перезаписан. Исправляется source token или генератор, затем
выполняется `pnpm tokens:build`.

## 21. Отключение линтера ради одного файла

Глобальное выключение rule запрещено. Локальное исключение требует комментария с причиной,
минимального scope и задачи на удаление, если это технический долг.

## 22. Данные только happy path

Компонент не считается готовым на трёх коротких demo-строках. Проверяются пустые значения,
переполнение, длинные имена, отсутствующие изображения, медленная сеть, 1/1000 строк и конфликт
версии.
